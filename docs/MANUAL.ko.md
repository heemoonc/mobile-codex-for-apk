# Mobile Codex for APK 사용 매뉴얼

[소개](../README.ko.md) · [English manual](MANUAL.en.md) · [최신 APK](https://github.com/heemoonc/mobile-codex-for-apk/releases/latest)

이 매뉴얼은 **0.3.9-apk-dev41**의 메뉴와 동작을 기준으로 합니다. 프로젝트 생성·환경 준비·빌드는 ChatGPT와 GitHub 연결 없이 사용할 수 있습니다. AI 대화에는 계정과 인터넷이 필요합니다.

## 1. 설치와 업데이트

- 릴리스 Assets에서 `Mobile-Codex-for-APK-*.apk`를 다운로드합니다. `Source code`는 설치 파일이 아닙니다.
- 기존 앱 위에 업데이트 설치하면 데이터를 유지할 수 있습니다. 패키지와 서명이 같아야 합니다. 앱 삭제 시 내부 프로젝트·도구·설정이 삭제될 수 있으므로 먼저 백업하십시오.
- 원본 Mobile Codex와 별도 앱입니다. 패키지는 `dev.mobilecodex.apk`이며 로그인·Linux·도구·인증이 자동 공유되지 않습니다.
- 접근성은 **Mobile Codex APK · 휴대폰 제어** 항목으로 구분합니다. 설치·권한 확인은 Android 화면에서 직접 진행합니다.

## 휴대폰 제어는 언제 필요한가요?

**휴대폰 제어를 켜는 이유:** Codex가 기기의 실제 화면을 확인하고 탭·입력·스크롤을 수행하여, 만든 앱의 화면과 사용 흐름을 함께 점검할 수 있도록 하는 기능입니다. 예를 들어 설치한 앱에서 버튼이 동작하는지, 입력한 내용이 표시되는지, 오류가 어느 화면에서 발생하는지 확인할 때 사용합니다. 코드 작성·환경 설정·빌드만 하거나 직접 앱을 조작하며 확인한다면 켜지 않아도 됩니다. APK 설치 확인과 권한 허용은 사용자가 직접 진행해야 합니다.

## 2. 개발 환경 준비

**도구 → Android 개발 환경 설정** 또는 **Android 개발 시작 → 개발 환경 준비**를 엽니다.

1. Linux를 설치·활성화합니다.
2. **2. 도구 다운로드·설치**를 누릅니다. 출처·용량·SDK 약관을 확인하고 직접 동의하십시오.
3. **개발 도구 실행 확인**을 누르고 로그와 결과를 확인합니다. 파일이 존재하는 것과 실행 성공은 구분합니다.
4. 프로젝트를 만들고 첫 빌드를 실행합니다. Gradle과 의존성은 처음 실행할 때 추가 다운로드됩니다.

도구 다운로드는 약 310 MiB, 최소 여유 공간은 1500 MiB입니다. Linux·Gradle·의존성·캐시는 별도 공간이 필요합니다. 고정 크기와 SHA-256을 확인한 Temurin JDK 17, Google SDK 35 / Build Tools 35.0.0, Commit451 커뮤니티 ARM64 aapt2를 사용합니다. aapt2는 Google 공식 ARM64 배포본이 아닙니다. 기존 `/opt/android`는 덮어쓰지 않습니다.

기본 경로는 JDK `/opt/android/jdk`, SDK `/opt/android/sdk`, aapt2 `/opt/android/bin/aapt2`입니다. 기존 프로젝트의 사용자 지정 경로는 자동 변경하지 않습니다. 진행 중에는 회전 표시와 상태·실행 로그를 확인하며 필요하면 중지하십시오. 화면을 닫아도 작업은 이어질 수 있지만 앱 재시작 후 자동 재개하지 않습니다.

## 3. 프로젝트 준비와 저장 위치

홈 또는 **도구 → Android 개발 시작**을 엽니다.

| 메뉴 | 사용 방법 |
|---|---|
| 새 Android 프로젝트 | 이름·패키지·폴더와 Java·Kotlin·Compose 템플릿을 선택합니다. |
| 폴더에서 가져오기 | Android 폴더 접근을 허용하고 내부 공간에 복사합니다. 원본을 보존하며 `.git` 이력은 복사하지 않습니다. |
| 소스 백업 ZIP 가져오기 | 이 앱에서 만든 소스 백업 ZIP을 복원합니다. 일반 ZIP은 먼저 폴더에 풀고 가져옵니다. |
| GitHub에서 가져오기 | `https://github.com/소유자/저장소`와 프로젝트 이름·폴더를 입력합니다. 공개 저장소는 인증 없이 가져올 수 있습니다. |

새 프로젝트와 가져온 복사본은 앱 내부 `android-projects` 공간에 저장됩니다. Linux에서는 선택 프로젝트의 같은 파일이 `/workspace`로 연결됩니다. Linux에 별도 복사본을 편집하는 구조가 아닙니다. 기존 **작업 폴더 선택**은 Android가 허용한 폴더를 연결하는 원본 기능이며 계속 사용할 수 있습니다. 공유 저장소는 실행 파일·심볼릭 링크를 제한할 수 있으므로 Android 빌드에는 내부 프로젝트를 권장합니다.

외부 소스는 빌드 전에 검토하십시오. Gradle 스크립트는 앱 권한으로 명령을 실행합니다. 프로젝트를 선택하기 전에는 프로젝트별 빌드·검증·Git 메뉴가 비활성화됩니다.

## 4. 코드 작성과 라이브러리

계정을 연결해 대화로 구현을 요청하거나 파일 편집기를 사용합니다. **Android 빌드 → Android 개발 도우미**에서 프로젝트를 진단하고 SDK·라이브러리 변경을 미리 본 뒤 적용합니다. 카탈로그는 고정 검증 프로필이며 최신 버전 추천 서비스가 아닙니다. 복잡한 Gradle·다중 모듈 프로젝트는 수동 검토가 필요합니다.

기능별 정상·실패·저장·재열기 동작을 검사하는 테스트를 작성하십시오. 기본 Java 템플릿을 만들었다는 사실만으로 기능 테스트가 준비되지는 않습니다.

## 5. 개발 단계와 자동 검증

**Android 개발 시작 → 개발 단계 · 자동 검증 · 매뉴얼** 또는 **도구 → 개발 진행 · 매뉴얼**을 엽니다.

- **개발 단계:** 현재 상태와 다음 작업을 확인합니다. 코드 작성·실사용 확인 체크는 사용자 보고입니다.
- **자동 검증:** 환경 확인 → 빌드·Lint·단위 테스트 → 선택한 API 모의 검사 순으로 실행합니다. 기본 `app` 모듈의 `assembleDebug`, `lintDebug`, `testDebugUnitTest`를 사용합니다.
- **사용 매뉴얼:** 단계별 안내와 중단 원인 해결 방법을 읽습니다.

실패·테스트 0개·건너뜀·실행 근거 미확인은 다음 단계를 중단합니다. `app/src/test`와 JUnit 의존성을 확인하십시오. API 모의 검사는 개발 도우미에서 준비 내용을 미리 보고 적용한 뒤 선택합니다. API 29~35 Robolectric 기준 검사는 실제 OS·권한·제조사·성능 검증을 대체하지 않습니다. QEMU 확인은 도구와 머신 초기화 검사이며 Android OS 부팅이 아닙니다.

소스나 도구 설정이 바뀌면 다시 검증합니다. 자동 검증은 코드·의존성 수정, APK 설치, 권한 허용을 대신하지 않습니다. 프로젝트·계정을 변경하면 다음 단계 실행을 중단합니다.

## 6. APK 빌드·저장·설치

1. **APK 만들기 · 저장**에서 프로젝트·도구 경로·Gradle 작업을 확인합니다.
2. **APK 빌드**를 누르고 터미널 로그와 종료 코드를 확인합니다.
3. **APK 새로고침 → 정보 확인**에서 패키지·버전·크기·수정 시각을 확인합니다.
4. **APK 저장**으로 내보낸 뒤 Android 설치 화면에서 직접 설치합니다.
5. 주요 기능, 회전, 종료·재실행, 저장 유지, 네트워크 실패를 확인합니다.

APK 존재나 수정 시각만으로 현재 소스의 빌드 성공·설치 성공을 보장하지 않습니다. 일반 APK 빌드 성공도 단위 테스트 통과를 의미하지 않습니다.

## 7. Git 저장과 GitHub 업로드

GitHub는 선택 사항입니다. 버전 이력·백업·협업·릴리스 배포에 유용하며 로컬 개발에는 필수가 아닙니다.

1. **Android 개발 시작 → 변경 저장 · GitHub 업로드**에서 변경 목록을 새로고침합니다.
2. **변경 비교**로 내용을 검토하고 저장할 파일만 선택합니다. 키·계정 파일·개인정보·빌드 캐시·테스트 결과 문서는 제외합니다.
3. 커밋 메시지를 입력하고 확인하면 선택 파일을 기기에 커밋합니다. 커밋만으로 업로드하지 않습니다.
4. 원격 주소·브랜치·커밋을 확인한 후 별도 **GitHub 업로드**를 실행합니다. 현재 브랜치의 커밋을 전송하므로 이전 커밋에도 비밀정보가 없는지 확인하십시오. 강제 업로드하지 않습니다.

앱은 GitHub HTTPS 주소를 사용하며 새 GitHub 저장소를 생성하거나 공개 범위를 변경하지 않습니다. 비공개 저장소는 해당 계정의 인증과 권한이 필요합니다. ChatGPT GitHub 연결, 이 앱의 번들 Git, Linux Git 인증은 별개입니다.

처음 만든 프로젝트에 Git 이력이 없다면 앱 터미널에서 초기화·원격·작성자를 설정하십시오. **이 화면의 Git 작업은 번들 Android Git을 사용하므로 Linux를 끈 앱 터미널에서 설정**한 뒤 빌드할 때 Linux를 다시 켭니다.

```sh
git init -b main
git config user.name "Your Name"
git config user.email "YOUR_GITHUB_NOREPLY_EMAIL"
git remote add origin https://github.com/OWNER/REPOSITORY.git
```

사용자 이름·이메일 설정은 인증이 아닙니다. 인증은 본인의 Git 자격 증명 방식으로 별도 구성하고 토큰·개인 키를 대화나 소스에 넣지 마십시오. 일반 폴더 복사와 소스 백업 ZIP에는 `.git` 이력이 포함되지 않습니다. GitHub 가져오기는 원격 연결과 최신 커밋을 포함하는 얕은 복제(`--depth=1`)입니다. 이전 전체 이력은 가져오지 않습니다. 소스 ZIP은 앱에 설치한 Linux·도구·인증 전체 백업이 아닙니다.

## 8. 문제 해결

| 증상 | 확인할 항목 |
|---|---|
| 실행 중 표시가 오래 유지됨 | 회전 표시·실행 로그·다운로드를 확인하고 필요 시 중지합니다. |
| Git 인증 실패 / 저장소 접근 불가 | 계정 권한과 번들 Git 인증을 확인합니다. ChatGPT 연결만으로 인증되지 않습니다. |
| 업로드 거절 | 원격 변경·브랜치를 확인합니다. 자동 강제 push 대신 터미널에서 이력을 검토합니다. |
| 테스트 0개 / NO-SOURCE | JUnit 의존성과 `app/src/test`의 테스트를 준비합니다. |
| 이전 APK가 보임 | 최근 빌드 종료 코드와 파일 정보를 함께 확인합니다. |
| 접근성이 켜져 있지만 작동하지 않음 | 올바른 APK 앱 항목인지 확인하고 사용자가 직접 껐다 켜 다시 연결합니다. |
| 다른 Android 버전이 미검증 | 현재 기기 빌드와 다른 OS 실기 검증은 별개입니다. |

앱 내 매뉴얼은 **개발 진행 → 사용 매뉴얼**에서 읽을 수 있습니다. 개발 도구 라이선스와 소스 구성은 [README](../README.ko.md), [서드파티 고지](../THIRD_PARTY_NOTICES.md)를 참고하십시오.

## 캐릭터 팩

새 설치에서는 기본으로 꺼져 있으며 캐릭터를 표시하지 않습니다. 설정에서 캐릭터 팩 사용을 켤 수 있습니다. 기존에 저장한 켜기·끄기 선택은 유지합니다.

## 이 앱 자체를 수정하려면

일반 앱 개발 환경은 위의 앱 메뉴에서 준비합니다. Mobile Codex for APK 자체를 수정·재빌드하는 경우에만 [개발자 빌드 안내](BUILDING.ko.md)를 따르십시오.
