# Build Mobile Codex for APK itself

[Overview](../README.md) · [한국어 빌드 안내](BUILDING.ko.md)

This guide is for contributors modifying and rebuilding Mobile Codex for APK itself. It is not the initial setup procedure for users building their own Android apps.

For normal use, install the released APK and open **Tools → Android development setup** to prepare Linux and the default JDK, SDK and aapt2. After you accept SDK terms and start installation/checks, the app handles downloads and default paths. Existing custom project settings are preserved. NDK and other tools for rebuilding this client’s native components are outside the default in-app setup.

Prepare JDK **17**, Android SDK **35**, Build Tools **35.0.0**, and Android NDK **r28c** for the native tools. The repository pins Gradle **8.13** and Android Gradle Plugin **8.9.2**. A fresh source checkout must prepare its runtime before the application build can pass runtime verification.

```sh
git clone https://github.com/heemoonc/mobile-codex-for-apk.git
cd mobile-codex-for-apk

# Review script options and prerequisites first.
python3 tools/prepare_runtime.py --help
python3 tools/prepare_devtools.py --help
python3 tools/build_native.py --help

# Prepare pinned runtime and development tools.
python3 tools/prepare_runtime.py
python3 tools/prepare_devtools.py
python3 tools/build_native.py --ndk "$ANDROID_NDK_HOME"

# Set ANDROID_HOME to your SDK, then build.
sh ./gradlew :app:assembleDebug
```

ARM64 Linux builds need compatible ARM64 JDK, native build tools and `aapt2`. Use `-Pandroid.aapt2FromMavenOverride=/path/to/aapt2` if needed. Do not assume desktop Android SDK binaries will execute unchanged on ARM64.

- Debug APK: `app/build/outputs/apk/debug/app-debug.apk`.
- Signing environment variables: `MOBILE_CODEX_KEYSTORE`, `MOBILE_CODEX_STORE_PASSWORD`, `MOBILE_CODEX_KEY_ALIAS`, `MOBILE_CODEX_KEY_PASSWORD`. Keep key material outside the repository.
- The diagnostic relay's default URL is blank in this source snapshot; configure it separately if needed.
- UI checks: run `npm ci`, then `npm test` with a supported Node.js version. See `package.json` → `engines`.
- When redistributing an APK, include the corresponding developer-tool sources generated by `python3 tools/prepare_devtools_sources.py` and all third-party notices.
